# Review the instructions before you act

Scope: every task.

Why: a wrong premise sends the work in the wrong direction. Explain an objection before doing the wrong work.

## Do's
### Give a concrete reason for an objection and propose a better approach

Review the user's instructions. State a wrong premise or error in the problem statement and propose a correction. Propose a simpler approach when one exists. Explain the reason so the user can learn from the work. Follow the instruction when review finds no objection.

```text
Hypothetical request: add a new parser dependency.
The existing dependency already parses the required format. I propose using it instead.
That avoids another package and lockfile change.
```

## Don'ts
### Do not accept a wrong premise or object without evidence

```text
The request says another parser is needed, so I will install one without checking.
I reject this approach because I do not like it.
```
